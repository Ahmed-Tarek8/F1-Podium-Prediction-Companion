* Split is chronological: train 2003–2018, validation 2019–2021, test 2022–2024 (a new regulation era).
* Primary metric PR-AUC (≈14% of driver-races are podiums); F1 uses a threshold tuned on validation.
* Removing the grid **and** qualifying groups together costs 0.118 test PR-AUC;

* Explanations (permutation importance, SHAP, LIME) agree on the top features; they describe what the **model** uses and are **not** causal claims.

## Key design decisions (short)

1. **No leakage in the final models:** every feature is computed from races strictly before the current one; standings come from the previous round; 300 rows are recomputed from scratch as a check; preprocessing statistics are fitted on the training block only (a deliberately leaky train+validation diagnostic never accesses test).
2. **Chronological split** instead of random, because rows within a season share cars and regulations.
3. **Preprocessing selection is tie-aware:** differences below 0.005 PR-AUC are treated as noise (they appear when library versions change), and ties keep the missing-value indicators.
4. **Imputation of season openers** (median + indicator) is a modelling convention, not a fact about those races.

## Known limitations

* **Era shift:** the test seasons are a new technical era; per-season test scores are reported.
* **Historical qualifying coverage:** complete qualifying data only exists from 2003, so older seasons cannot use qualifying features.
* Grid and qualifying are highly correlated — use the joint ablation / joint permutation numbers.
* Validation was reused for preprocessing, hyper-parameters, early stopping and the threshold, so validation scores are mildly optimistic.
* Each driver is scored independently; nothing forces exactly three podiums per race.
* The saved `.joblib` models contain the notebook's own `Preprocessor` class; the notebook retrains everything and does not depend on them.
